# UI 重设计方案（2026-11-15）

基于 14 个页面的实机截图（1440×900）逐页评估。

---

## 一、页面与关键流程梳理

### 1.1 信息架构（现状）

```
标书工作台
├── 内容生成
│   ├── 投标文件          ← 核心流程，7 步
│   └── 可行性研究报告Beta  ← 6 步
├── 模版设置              ← Word 导出模板
├── 知识库
│   ├── 文档知识库        ← 素材/案例
│   └── 资信库            ← 企业资质
├── 标书检查
│   ├── 标书查重
│   ├── 废标项检查
│   └── 暗标合规检查
├── 其他功能
│   ├── 产物库
│   ├── 图片知识库        （未开放）
│   ├── Word批量转换      （未开放）
│   └── 插件管理          （未开放）
└── 设置
```

**二级导航是「先选一级、再在页面里选二级」**，不是折叠菜单。这个模式本身没问题，但**每次切换都要两次点击**。

### 1.2 投标文件的核心流程（7 步）

```
STEP 01 选择标书     上传招标文件 → 解析成 markdown
STEP 02 生成设置     8 个配置页签（写哪/我有方案/知识库/写多少/插图/怎么写/长啥样…）
STEP 03 招标文件解析  并发跑 7 项分析，看结果
STEP 04 目录生成     15 章 101 节点，可增删改
STEP 05 全局事实     项目名称/金额/工期等，保证全文一致
STEP 06 正文生成     逐章 AI 生成
STEP 07 导出         选模板 → 出 docx
```

**这是一个 7 步长流程，中间有多次几十秒到几分钟的 AI 等待。**

## 二、不合理之处（按严重程度排序）

### P0-1　没有全局步骤指示器 —— 用户不知道自己在哪

**证据**：每个页面只有一个 `STEP 01` / `STEP 04` 的小标签，没有任何地方显示「共几步、当前第几步、后面还有什么」。

截图里 STEP 01 和 STEP 04 长得几乎一样（都是左上角一个蓝色小字）。用户走到第 4 步时，**完全不知道自己还剩 3 步**。

**为什么严重**：7 步长流程 + AI 等待，用户最需要的就是「我还差多少」。缺这个，会让人怀疑是不是卡住了。

**改进**：

```
顶部横向步骤条（固定在内容区顶部）

 ①──②──③──④──⑤──⑥──⑦
 ✓  ✓  ✓  ●  ○  ○  ○
选择  设置  解析  目录  事实  正文  导出

- 已完成：实心蓝点 + 勾
- 当前：蓝底白字 + 脉冲动画
- 未到：灰色空心
- 可点击回跳（已完成的步骤）
- 每步下方显示状态副标题（如「101 个节点」/「12,748 字」）
```

### P0-2　同一个错误弹两次

**证据**（截图 02-bid-step01）：右上角**两个一模一样的**「出错了 / 步骤不能为空」。

**原因**：`updateStep` 的 `catch` 和全局 toast 各弹一次。

**改进**：
- Toast 加 `dedupeKey`，5 秒内相同文案只显示一个
- 错误提示区从右上角浮层改为**内联在出问题的区域**（如步骤条下方），因为浮层会遮挡操作

### P0-3　空态页面浪费 80% 空间

**证据**：

| 页面 | 问题 |
|---|---|
| 知识库（1 个文档） | 整个右栏只有一个卡片，下面全是空白 |
| 模板设置 | 左右两个大白块，各一个「新建」按钮（重复） |
| 标书查重（无重复） | 中间一个大图标 + 两行字，占满整屏 |

**改进**：

**① 模板页**：把「新建第一个模板」收到顶部工具栏，右侧预览区改成「系统预置模板」列表（提供 3-5 个开箱可用的模板），而不是一片空白。

**② 知识库**：文档列表改为**表格/列表视图**（文件名、字数、状态、时间、操作），带排序和批量操作。单条数据也不会显得空。

**③ 查重无结果**：不要占满屏，收成一个成功状态卡片（绿色勾 + 「未发现重复」），下方立刻显示**下一步建议**（去废标项检查 / 导出报告）。

### P0-4　左侧「生成过程」栏长期是空的

**证据**（截图 03-bid-step03）：目录生成页左边一个 260px 宽的栏，只有「生成进度 100%」和一个「等待生成任务启动」的空框。

**问题**：这个栏占了 20% 宽度，但 90% 时间没内容。真正重要的目录树被挤在中间。

**改进**：**折叠式侧栏**。任务运行时展开显示实时日志/进度；空闲时自动收起成一条 40px 的细条（只留进度环），把空间让给目录树。

### P1-1　配置页签名称像黑话

**证据**（截图 02-bid-step01）：

```
写哪 / 我有方案 / 知识库 / 写多少 / 插图吗 / 怎么写 / 长嘛样
```

- 「写哪」「插图吗」「长嘛样」是口语，**不像专业工具**
- 「长嘛样」还带方言
- 前 6 个字面意思不明确（「写哪」= 范围？「怎么写」= 生成策略？）

另外 **7 个页签横排在一行**，超出容器后有横向滚动（截图里第 7 个「长嘛样」被切了一半）。

**改进**：

| 现在 | 改为 |
|---|---|
| 写哪 | 生成范围 |
| 我有方案 | 原方案参考 |
| 知识库 | 知识库引用 |
| 写多少 | 字数控制 |
| 插图吗 | 配图设置 |
| 怎么写 | 生成策略 |
| 长嘛样 | 导出模板 |

页签改为**左侧竖排**（7 项竖排不占横向空间，且能显示每项的状态摘要），右侧显示当前项的配置。

### P1-2　底部悬浮工具条遮挡内容

**证据**（截图 03-bid-step03）：工具条浮在目录列表上方，**遮住了最后两行**。

**改进**：
- 工具条改为**贴底固定**（非悬浮），内容区加 `padding-bottom` 预留高度
- 或者：主操作按钮（下一步）放页面顶部右侧，次要操作（首页/上一步/重置）放底部

### P1-3　目录节点标题重复

**证据**：`第一章 第一章 编制说明与项目理解`、`第二节 第二节 项目概况…`

**原因**：后端存 title 时已经带了「第一章」，前端渲染又拼了一次。

**改进**：数据层修（存纯标题，编号单独存 `number` 字段）；UI 层加「防重复前缀」兜底。

### P1-4　资信库是超长表单，没有分组和进度

**证据**（截图 09）：基本信息页签下 20+ 个字段，两列平铺，一屏放不下，**没有分组标题**。

**改进**：
- 按「工商信息 / 联系方式 / 规模指标 / 经营范围」加中间分组标题
- 每页签顶部显示**完成度**（如「基本信息 8/12 已填」）
- 必填项用 `*` + 顶部「还有 4 项必填」提示

### P2-1　登录页 Logo 文字挤压

**证据**：Logo 方块里是「标书/工作」两行，像溢出。

**改进**：改成纯图形标（几何形状或首字母「标」），文字放右侧作为纯文本。

### P2-2　产物库每行一个大「下载」按钮

**证据**：每行右侧一个 88px 宽的主色按钮，视觉上非常重（一排 8 个蓝按钮）。

**改进**：主操作改为图标按钮（↓），hover 才显示文字；或整行可点击，右侧只留一个 `⋯` 菜单。

### P2-3　设置页残留桌面版项

**证据**：「自动更新渠道 AtomGit」「GPU 硬件加速」「存储空间」——Web 版都没意义。

**改进**：按部署模式（desktop / web）条件渲染，Web 版隐藏这些。

### P2-4　查重页状态自相矛盾

**证据**：右上角「分析中...」，但四个页签都显示「已完成」。

**改进**：状态机加互斥校验，或在「分析中」时页签不显示「已完成」。

## 三、重设计方案

### 3.1 三条设计原则

**① 进度可见** —— 多步流程必须有全局进度，让用户时刻知道「还剩几步、卡在哪」。

**② 空间给内容** —— 侧栏能收则收，空态不占整屏，工具栏不遮内容。

**③ 术语专业化** —— 界面文案不用口语/方言，用行业标准说法。

### 3.2 布局重构

**现在**（内容区直接铺满，无顶部结构）：

```
┌────────┬──────────────────────────────┐
│        │ STEP 01                      │
│ 侧边栏  │ 选择标书                      │
│ 260px  │ ┌──────────────────────────┐ │
│        │ │  内容                     │ │
│        │ └──────────────────────────┘ │
│        │      [重置][首页][下一步]       │
└────────┴──────────────────────────────┘
```

**改为**（加顶部步骤条 + 底部固定操作栏）：

```
┌────────┬──────────────────────────────────────┐
│        │ ┌ ①选择 ─ ②设置 ─ ③解析 ─ ④目录 ─ ... │ ← 步骤条（吸顶）
│ 侧边栏  ├──────────────────────────────────────┤
│ 240px  │  选择标书                    [重新解析] │ ← 页头
│ (可收)  │  上传招标文件，解析成可编辑文本           │
│        │ ┌────────────────────────────────┐   │
│        │ │                                │   │
│        │ │  内容区（独立滚动）              │   │
│        │ │                                │   │
│        │ └────────────────────────────────┘   │
│        ├──────────────────────────────────────┤
│        │ 上一步            重置  首页   下一步 → │ ← 固定操作栏
└────────┴──────────────────────────────────────┘
```

关键变化：
1. **步骤条吸顶**，始终可见
2. **操作栏固定底部**，不悬浮、不遮挡
3. **侧边栏 240px 可收起**（收到 64px 只留图标）

### 3.3 步骤条组件设计

```
已完成              当前              未开始
   ✓                 ●                 ○
  ──────            ──────            ──────
 选择标书           目录生成           正文生成
 4182 字            101 节点           —

状态色：
- 完成：--yb-success (#168a4a) 实心
- 当前：--yb-primary (#2174fd) 实心 + 外圈光晕
- 未开始：--yb-text-muted (#98a2b3) 空心
- 出错：--yb-danger 实心 + 感叹号
```

**交互**：
- 已完成步骤可点击回跳（hover 显示「回到这一步」）
- 当前步骤不可点
- 未来步骤不可点，但 hover 显示「完成当前步骤后解锁」

### 3.4 生成设置页重构

**现在**：7 个横排页签 + 单页长滚动

**改为**：左竖排导航 + 右侧配置面板

```
┌─────────────┬────────────────────────────────┐
│ 生成范围     │  字数控制                    │
│ 原方案参考   │  ─────────────────────────  │
│ 知识库引用   │  全文最少字数                  │
│ ▸字数控制    │  [30000          ] 字        │
│ 配图设置     │                              │
│ 生成策略     │  每节目标字数                  │
│ 导出模板     │  [1500           ] 字        │
│             │                              │
│ 已完成 3/7   │  影响：全文约 15 章 × 1500 字  │
└─────────────┴────────────────────────────────┘
```

好处：
- 7 项竖排有空间显示**每项的状态摘要**（如「字数控制 · 30000 字」）
- 左侧显示**总完成度**
- 右侧可以放**实时影响提示**（改字数 → 立即告知预计总字数）

### 3.5 目录页重构

**现在**：三栏（生成过程 260 / 目录树 / 详情）+ 底部悬浮条

**改为**：两栏 + 可折叠左侧

```
┌────┬─────────────────┬─────────────────────┐
│ ◐  │ 目录结构 (101)    │ 第一章 编制说明       │
│进度│ ─────────────── │ ──────────────────  │
│ 环 │ ▸ 第一章 ...     │ 开篇立信之章。说明本  │
│    │   ├ 1.1 编制依据 │ 技术标的编制依据（招  │
│ 点 │   ├ 1.2 项目概况 │ 标文件、8部国家验收  │
│ 击 │   └ 1.3 招标范围 │ 规范、施工图纸...     │
│ 展 │ ▸ 第二章 ...     │                     │
│ 开 │                  │ [编辑] [加子目录]     │
│日志│                  │ [删除]              │
└────┴─────────────────┴─────────────────────┘
```

左侧空闲时只占 48px（一个进度环），需要看日志时点击展开。

### 3.6 空态设计规范

所有空态统一三段式：

```
     [图标 48px，浅灰]

     还没有 XX
     一句话说明为什么需要它

     [+ 主要动作]  [次要动作（可选）]
     ─────────────────────
     💡 或者：使用系统预置的 XX
```

**关键**：空态必须给出**下一步可执行的动作**，不能只有「暂无数据」。

### 3.7 配色与字体（保持现有体系）

现有 token 已经合理，只做微调：

```css
/* 保持 */
--yb-primary: #2174fd        /* 主色，用于主要操作 */
--yb-success: #168a4a        /* 完成态 */
--yb-border: #e6e9f0

/* 新增 */
--yb-danger: #e5484d         /* 错误态 */
--yb-warning: #f5a524        /* 警告态 */
--yb-step-inactive: #cbd5e1  /* 未完成步骤 */

/* 间距体系（8px 栅格） */
--space-1: 4px   --space-2: 8px   --space-3: 12px
--space-4: 16px  --space-6: 24px  --space-8: 32px
```

字号：
```
页面标题   22px / 600
区块标题   15px / 600
正文       13px / 400
辅助说明   12px / 400  (--yb-text-muted)
```

## 五、建议实施顺序

**第一批（骨架）**
1. 全局步骤条组件 + 接入投标文件 7 步
2. 底部操作栏改固定定位
3. Toast 去重

**第二批（空间）**
4. 目录页左侧栏可折叠
5. 模板页 / 知识库 / 查重页空态重构

**第三批（细节）**
6. 配置页签竖排 + 文案专业化
7. 目录标题去重
8. 资信库分组 + 完成度

**第四批（收尾）**
9. 登录页 Logo
10. 产物库行操作
11. 设置页桌面项条件渲染
