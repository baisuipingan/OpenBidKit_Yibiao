## 一、新迁移的两个模块

### 1.1 可行性研究报告（完整迁移）

**规模**：前端 8 个页面共 2,367 行，13 个 IPC 接口。之前只是 `Promise.reject('即将上线')` 的占位。

**实现**：

```
feasibility_reports   报告主表（6 步状态 + 项目信息 + 分析 + 目录 + 参数）
feasibility_sources   资料源文件（解析后的 markdown）
```

**关键设计**：
- **项目信息用 JSONB**：10 个字段（项目名称/类型/行业/建设单位/投资额…），
  用 JSONB 存，后续加字段不用迁移
- **目录树整体存 JSONB**：目录是嵌套结构，建表反而复杂
- **章节正文按 nodeId 定位更新**：`updateOutlineNodeContent` 递归查找后原地写入
- **资料去重**：按内容 SHA256，同一份文件重复导入自动跳过

**复用已有能力**：`docparse.ToMarkdown` 解析 Word/PDF/Excel，
不需要新写解析逻辑。

**验证**：STEP 01 表单完整渲染（10 个字段）→ 填表 → 下一步 → STEP 02 资料文件页，零错误。

### 1.2 资信库（完整迁移）

**规模**：12 个接口，之前只返回空快照（会导致 `Cannot read properties of null`）。

**数据模型取舍**：

```
credential_profiles   企业档案（每租户一份，JSONB）
credential_items      证书/人员/业绩/材料/图片（kind 区分，JSONB）
```

**为什么不用 5 张表**：证书/人员/业绩的字段差异大且会随业务变化。
建 5 张表意味着每加一个字段都要改 schema，而结构本来是前端定义的。
用 `kind + JSONB`，后端只负责存取。

**保存语义**：`saveProfile` 做**浅合并**而不是整体替换 ——
前端可能只传改动的字段（如只改公司名），整体替换会清空其他字段。

**验证**：8 个页签（基本信息/公司介绍/资质/员工/业绩/财务/其他/水印）、
20+ 表单字段完整渲染，零错误。

### 1.3 剩余 4 项为什么不迁移

| 功能 | 判定 |
|---|---|
| 图片知识库 | **前端页面不存在**（只有菜单项和图标），是桌面版未开发功能 |
| AI评标 | 同上，无前端页面 |
| Word批量转换 | 需本机 Office/Ghostscript 转 PDF，浏览器做不到 |
| 插件管理 | 插件是本地可执行扩展，Web 端无法加载 |

前两个不是"未迁移"而是"未开发"，后两个是环境限制。
统一用 `webUnavailableNotice` 提示，点击弹说明而不是报错。

## 二、广告位与品牌清理

### 2.1 移除的广告/运营模块

| 模块 | 原行为 |
|---|---|
| **侧栏广告卡** | 从 `analytics.agnet.top/ads` 拉广告图，8 秒轮播 |
| **加群二维码** | 侧栏按钮 + 弹窗，二维码支持远程替换 |
| **远程公告弹窗** | 启动时强制弹窗（`analytics.agnet.top/notice`） |
| **精选资源页** | 作者推荐内容（`analytics.agnet.top/resources`） |
| **打赏提示** | 累计使用 N 小时后弹出「请作者吃顿饭」 |
| **使用埋点** | 上报设备 ID、页面访问、配置组合到第三方 |
| **更新日志** | 从作者服务器拉取版本更新说明 |
| **GitHub / wiki 链接** | 关于页的仓库地址、作者 wiki、离线授权 |

### 2.2 埋点改 no-op 而不是删调用

`trackPageView` / `trackConfigUsage` / `trackAdClick` 等函数散布在 10+ 个页面。
逐个删调用点价值低，还会让后续从上游同步代码时冲突。

改成**保留同名导出但函数体为空**：

```ts
/** 页面访问：不再上报 */
export function trackPageView(_page: string): void {}
```

调用点一行都不用动。

### 2.3 品牌改名

「易标」→「标书工作台」，共 13 个前端文件 + 3 个后端文件：

| 位置 | 改前 | 改后 |
|---|---|---|
| 登录页标识 | 易标 | 标书工作台 |
| 侧栏品牌 | 易标 / 投标工具箱 | 标书工作台 / 投标全流程助手 |
| 后端 bootstrap | 易标投标工具箱 | 标书工作台 |
| AI 提示词 | 你是易标投标助手的自检任务 | 你是标书工作台的自检任务 |
| 服务商名称 | 易标官方API | 标书工作台官方API |

### 2.4 关于页改造

原来是「信息与授权」卡片，含 GitHub 仓库、作者 wiki、离线激活授权（桌面版专属）。

改成「服务信息」：

```
运行方式   Web 版（浏览器访问，数据存于服务端）
数据存储   部署方自有服务器，不出本机网络
登录方式   账号密码（由管理员分配）
```

### 2.5 侧栏「文档」按钮

原来跳 `wiki.agnet.top`（作者的外部站点）。

改成打开**内置使用说明对话框**，内容涵盖各模块用途，不依赖任何外部站点。

### 排查过程中发现并修复的

1. **登录页仍显示「易标」** —— 源码已改，但后端 `bootstrap.appName` 硬编码了旧名。
   这类「前端改了但显示没变」的问题，要从数据源头查。

2. **`file.getPathForFile` 未实现** —— 前端 12 处调用它取文件路径，
   Web 端拿不到本地路径。补上：返回 `upload://` 伪路径 + 后台上传。

3. **`templates` 整组接口缺失** —— 模版设置页 404。建表 + 7 个 handler。

4. **`config.save` 缺失** —— 设置页保存 404。加统一入口按字段分发。
